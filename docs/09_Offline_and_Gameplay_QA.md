# 오프라인 자산과 플레이 안정화 검증

## 구현 범위

- Phaser 3.80.1 CDN 의존성을 제거하고 npm 배포본의 원본 파일과 MIT 라이선스를 함께 포함했습니다. 고정 SHA-512로 다운로드를 확인하고, 포함 파일의 SHA-256을 빌드 때 검사합니다.
- 기본 퍼즐 자산은 모두 상대 경로입니다. CSP가 외부 리소스와 외부 fetch를 허용하지 않습니다. 시스템 폰트와 코드 기반 도형·오디오를 사용합니다.
- 부활 시 정류장의 차량 한 대를 만석으로 만들 수 있는 승객을 대기열 앞에 모읍니다. 나머지 승객 순서와 전체 승객 수를 보존합니다. 이 복구가 불가능하면 부활 광고를 제안하지 않습니다.
- 광고 요청부터 지급·저장까지 중복 요청을 차단합니다. 부활 완료 시 stage뿐 아니라 roundId도 비교해 같은 스테이지를 재시작한 뒤 도착한 이전 응답을 무시합니다.
- 광고 처리 중 재시작/부스터/차량 탭과 자동 탑승을 잠급니다. 판을 다시 만들면 이전 애니메이션과 누적 타이머를 정리하고 빙결 해제 조건을 다시 반영합니다.
- 탑승으로 대기열 앞 색상이 바뀐 직후에도 실패를 판정하여 정류장이 가득 찬 채 멈추는 상황을 처리합니다.

## 실행한 검증 (2026-11-17, Windows)

- `npm run check`: 저장소·레벨 구조·플랫폼·플레이 규칙·iOS 템플릿·소스 HTTP 경로·오프라인 자산 검사 통과.
- `npm run validate:bundle`: `dist` 생성과 빌드된 Phaser/모듈/JSON HTTP 경로 검사.
- 새 로컬 브라우저에서 CDN 없는 화면 렌더링, 셔플 차감, 재시작 후 부스터 수 유지, 실제 광고 연결이 없을 때 무지급을 확인했습니다.
- 390×844 화면에서 헤더·정류장·보드·하단 버튼 표시를 확인했습니다. 브라우저 오류/경고 로그는 없었습니다. [화면](qa/offline-iphone-preview.jpg).
- 자동 플레이 검증은 부활 시 실제 탑승 가능 여부, 승객 보존, 연타, 같은 스테이지 재시작 후 늦은 응답, 취소, 저장 실패를 포함합니다.

## 검증의 한계와 다음 작업

- 브라우저 검증은 로컬 HTTP 서버에서 실행했습니다. PC 전체 네트워크를 끄거나 실제 iPhone의 비행기 모드로 테스트한 결과는 아닙니다. 자산 참조 검사와 브라우저 CSP로 외부 자산 의존성을 제한했습니다.
- 웹사이트의 오프라인 캐시/PWA 설치는 구현하지 않았습니다. 로컬 서버 또는 게임 자산을 제공하는 앱 호스트가 필요합니다.
- 실제 네이티브 SDK 광고·구매·iCloud 및 WKWebView 번들 로딩은 아직 미검증입니다. 이 변경은 해당 서비스 구현을 대신하지 않습니다.
- 부활은 적어도 차량 한 대가 출발할 수 있도록 복구하며 그 뒤 모든 선택의 클리어를 보장하지는 않습니다.
- 이 검증 당시 샘플에 있던 해제색 부재·다른 색 터널 소비 문제는 이후 수정했습니다. 현재는 단계별 20레벨과 공유 솔버를 사용합니다. 최신 콘텐츠 검증은 [20레벨 기록](10_Level_Verification.md)을 참고합니다.
