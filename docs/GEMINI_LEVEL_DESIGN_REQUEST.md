# Gemini 복사·붙여넣기 요청문

아래 내용을 회사 게임 개발 Gem에 그대로 전달해 주세요. 답변은 이 채팅에 붙여넣으면 됩니다. 코드 적용과 실행 검증은 Codex가 담당합니다.

---

Bus Fever: Car Jam이라는 서버 없는 iOS 캐주얼 퍼즐의 초반 20레벨 진행을 설계해 줘. IAP와 AdMob 보상형/전면 광고를 사용하지만 광고나 결제 없이 모든 레벨을 클리어할 수 있어야 한다. 회사 Gem의 게임 개발 지침을 적용하되, 아래 실제 구현 상태를 기준으로 간결하고 바로 적용할 수 있게 답해 줘.

현재 엔진:

- 격자 위 차량을 탭하면 전방 경로가 비어 있고 정류장에 빈 슬롯이 있을 때 출차한다.
- 차량 길이는 1칸 또는 2칸, 승객 정원은 각각 4명/6명이다. 오래된 기획의 '3명 매치'는 현재 엔진과 다르니 이 설계에서는 4명/6명 기준을 유지한다.
- 정류장 슬롯은 4개다. 선두 승객은 같은 색 DOCKED 차량에 타고, 만석 차량은 출발해 슬롯을 비운다.
- 정류장이 모두 찬 상태에서 선두 승객이 탈 차량이 없으면 실패한다. 부활은 조건을 만족할 때 대기열을 정리하여 차량 1대를 출발 가능하게 한다.
- mystery는 출차 후 정류장에 도착하면 본래 색을 공개한다.
- frozen은 지정된 해제색 승객이 대기열 맨 앞에 오면 풀린다.
- tunnel은 현재 '뒤 승객을 먼저 태우기' 구현이지만 다른 색을 소비해 색별 승객 수가 깨지는 문제가 있다. 같은 색 승객만 태우면서 대기열을 우회하도록 고치는 안을 우선 검토해 줘.
- 색상은 red, blue, yellow, green, purple, cyan이다. 색약 표시는 기호도 함께 사용한다.
- 초기 재화: 코인 120, 셔플 2회, VIP 1회. 부스터 사용을 강제하는 난이도는 금지한다.

현재 레벨 데이터는 좌표 레이아웃이 아니라 생성기에 전달하는 시드다. 형식은 아래와 같다.

```json
{
  "stages": [
    {
      "stage": 1,
      "seed": 1,
      "slotLimit": 7,
      "cars": [
        { "gimmick": "normal", "stack": ["red"] },
        { "gimmick": "mystery", "stack": ["yellow"] },
        { "gimmick": "frozen", "stack": ["purple", "blue"] },
        { "gimmick": "tunnel", "stack": ["cyan", "cyan"] }
      ]
    }
  ]
}
```

현재 생성기는 cars의 태그를 차량에 반복 배정한다. stack 첫 색이 차량색, frozen은 마지막 색이 해제색이다. slotLimit은 저장되지만 실제 정류장 4개와 연결되어 있지 않으므로 이를 바꾸는 것으로 난이도를 조절한다고 가정하지 마라. 현재 샘플은 첫 레벨부터 전 기믹이 섞여 있고 해제색이 아예 없는 문제도 있다. Codex가 생성기·솔버와 데이터 구조를 고칠 예정이다.

원하는 산출물:

1. 레벨 1~20의 표: 학습 목표, 차량 수, 색상 수, 새 기믹 수, 목표 출차 순서의 특징, 실패를 유도하는 선택, 목표 플레이 시간 범위.
2. 1~5 normal, 6~10 mystery, 11~15 frozen, 16~20 tunnel의 단계별 교육 문구. 한 문장씩, 게임 화면용 쉬운 한국어.
3. frozen의 해제색이 실제로 먼저 도달 가능한지, tunnel이 색별 승객 수를 보존하는지 확인할 설계 불변식. 설명 최대 6개.
4. 생성기/솔버가 검증해야 할 조건을 최대 8개로 정리. 잘못된 시드를 통과시키지 않아야 한다.

각 레벨의 클리어 보장은 실제 솔버 실행 후 Codex가 확인한다. 직접 실행하지 않은 데이터를 '클리어 검증 완료'라고 쓰지 마라. 이번 답변에는 대형 코드나 검증되지 않은 좌표 JSON 대신 위 네 가지 산출물만 제공해 줘.
